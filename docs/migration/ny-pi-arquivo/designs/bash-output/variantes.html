Saída do bash: 3 variantes

Mesmo conteúdo nas quatro: um sucesso com saída longa (7 linhas, mostra as 5 últimas), um erro e um comando sem saída. Cores do tema pi-escuro. Todas mantêm: uma linha por chamada, resumo após ·, português, duração só a partir de 1 s.

✓ ▸ bash   mkdir -p /tmp/out
  • O fundo verde/vermelho pinta o bloco inteiro: muita tinta para o que é status. O │ e o ⋯ competem com a saída.

1 · Silêncio sem fundo; o status é só o glifo

✓ bash  cd ~/code/pi-harness && rg -ln "renderCall|renderResult" ext… · 7 linhas
      extensions/image-open/image-open.test.ts
      ~/.pi/agent/npm/node_modules/pi-code/extensions/todo.ts

✕ bash  node --test tests/x.test.mjs · código 1 · 1.2s
      Error: Cannot find module 'tests/x.test.mjs'
✓ bash  mkdir -p /tmp/out
  • A favor: o mínimo de tinta; a saída fica alinhada sob o comando, em cinza; o resto vira uma nota no fim (+3 linhas · ctrl+o), onde o olho termina.
  • Contra: sem fundo, blocos seguidos se separam só pelo espaço em branco; erro depende da cor vermelha (o ✕ segura o sentido sem cor).

● bash  $ node --test tests/x.test.mjs · código 1 · 1.2s

  Error: Cannot find module 'tests/x.test.mjs'
● bash  $ mkdir -p /tmp/out
  • A favor: o fundo deixa de ser verde: um cinza único agrupa a chamada, e o status vira só a faixa de 1 coluna e o ponto; o $ diz "isto é um comando" sem rótulo.
  • Contra: no terminal a faixa é um caractere (▎), não 2 px; cantos arredondados não existem, então o cartão é um retângulo.

  • A favor: o conector ╰ liga resultado à chamada com um só traço (o mesmo gesto do ⎿ do Claude Code, que o harness já imita em atalhos); a saída não ganha uma barra por linha.
  • Contra: o ponto colorido sozinho carrega o status; daltônicos dependem do código 1 escrito.
