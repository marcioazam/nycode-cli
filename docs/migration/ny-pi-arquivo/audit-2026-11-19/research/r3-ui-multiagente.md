## Protocolos e formatos

- **A2A**: Agent Card (JSON: identidade, skills, endpoint, auth), Task com ciclo de vida e ID, Message com Parts, Artifact; JSON-RPC 2.0 sobre HTTP(S), SSE e push por webhook. Pensado para agentes opacos entre organizações, não para subagentes de um mesmo processo. Fonte: https://a2a-protocol.org/latest/topics/key-concepts/ (lido). Nomes dos estados de Task: NÃO lidos.
- **ACP (Agent Client Protocol)**: editor/IDE ↔ agente de código, JSON-RPC sobre stdio (local) ou HTTP/WebSocket (remoto, em andamento), reaproveita JSON do MCP. É protocolo UI↔agente, não agente↔agente. Fonte: https://agentclientprotocol.com/overview/introduction (lido; sessões/permissões não cobertas na página). Zed e o `gt mayor acp` do Gas Town o usam.
- **MCP Tasks** (spec 2025-11-25, experimental): máquinas de estado duráveis com ID gerado pelo receptor, `tasks/list`, `tasks/cancel`, polling e resultado diferido. Fonte: https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks.md (snippet). Sampling e elicitation: NÃO lidos nesta rodada.
- **Mailbox**: Claude Code teams (`SendMessage`, `config.json` com `members`), Gas Town (mailboxes entre agentes longos + handoffs síncronos), Warp (caixa de notificações para o humano).
- **Blackboard / contexto compartilhado**: DeLM (agentes pegam tarefas de uma fila e publicam num contexto compartilhado, sem agente principal) e bMAS; resultado de ganho é dos próprios autores. Fontes: https://arxiv.org/html/2606.10662 ; https://arxiv.org/pdf/2507.01701v1.pdf.
- **Overhead**: A2A e ACP chegam a "task-ready" em 1 round trip, MCP legado em 3 (arXiv 2610.30151); irrelevante para processos locais, relevante só se o grafo cruzar rede.
- **Formatos declarativos**: CrewAI `agents.yaml`/`tasks.yaml`; AutoGen Team JSON (`component_type`, round-trip com editor visual); Oracle Agent Spec (arestas de controle e de dados separadas, validação estática); A2A Agent Card (JSON); Claude Code `~/.claude/teams/{team}/config.json` e tarefas em `~/.claude/tasks/{team}/` (fonte secundária, repositório de usuário).
- **Responsabilidade e propriedade de arquivos**: Claude teams delegam o particionamento ao usuário ("each teammate owns a different set of files"); issue pede um conjunto de arquivos exclusivo por nó e recusar/serializar sobreposição (https://github.com/anthropics/claude-code/issues/109707); Polywave impõe arquivos disjuntos antes, durante (hook PreToolUse) e depois (auditoria); Claim Plane distingue escopo comprometido (reserva escrita) e contingente (promovido na primeira escrita); blueprint do Stack Overflow recomenda impor só no limite de arquivo exato e deixar diretório/módulo como aviso.

## Padrões de UX recomendados para o ny-pi

1. **Tela de frota como tabela agrupada por estado, não por árvore** (Needs input no topo, depois Working, Completed), com contagem no topo e uma linha por agente (ícone, nome, resumo de uma linha, idade). Evidência: C5, C7, C23.
2. **Vocabulário de estados fechado e com cor**: Working, Needs input, Idle, Completed, Failed, Stopped (+ Blocked para dependência). Evidência: C5, C14, C24.
3. **Peek antes de attach**: Space abre prévia do transcript, Enter anexa, ← volta; subagentes da árvore profundidade 3 entram na mesma lista (a agent view da Anthropic os omite, o que é uma falha a evitar). Evidência: C5, C6, C2.
4. **Caixa de "precisa de você"** (Complete / Request / Error) que cobre também os filhos, com Enter indo direto ao agente bloqueado. Evidência: C14 (a falha dela: só cobre o pai).
5. **Grafo como visão derivada de arquivo declarativo**, não como estado separado: o YAML/JSON é a fonte; TUI e web mostram o mesmo arquivo; exportação para Mermaid/DOT de graça. Evidência: C32, C33, C34, C36.
6. **Aresta tipada**: separar controle (depende de/espera) de dados/mensagem (canal), como no Agent Spec e no `addBlockedBy` das tarefas do Claude. Evidência: C36, C1.
7. **Desenho do grafo em camadas (Sugiyama) com box-drawing, nó = caixa de 1–3 linhas** (nome, papel, estado) e foco por teclado; Braille/Kitty só como realce opcional com fallback. Evidência: C38, C39, C40.
8. **Mouse opcional**: clique para selecionar nó e rolar, via SGR 1006, sem tirar o teclado como caminho principal. Evidência: C41.
9. **Visão web local (xyflow + ELK) como segunda tela para edição pesada**, falando com o harness por WebSocket; o terminal continua sendo o controle (aprovar, interromper). Evidência: C43; a sincronização é projeto novo (nenhuma fonte lida mostra um produto assim).
10. **Propriedade de arquivos por nó com validação antes de iniciar** (globs disjuntos por onda, recusa ou serialização automática) e aplicação dura só no arquivo exato; diretório/módulo vira aviso. Evidência: C4, C50.
11. **Campo "responsabilidade" curto + ferramentas + modelo + glob de arquivos no cartão do nó**, editável no gerenciador (papéis tipo architect que nunca codifica). Evidência: C13, C17, C20.
12. **Custo por agente e total sempre visível** (tokens/USD por nó e acumulado da árvore), com teto por filho. Evidência: C19 (ACU por filho), C18 (Factory não mostra por worker: lacuna), C28, C49.
13. **Controles de intervenção em uma tecla**: pausar orquestrador, parar nó, enviar mensagem, responder opção numerada, replanejar e retomar. Evidência: C17, C5, C19.
14. **Escrita single-threaded por padrão no grafo**: nós extras são revisores/consultores; paralelismo de escrita só com arquivos disjuntos. Evidência: C20, C47.
15. **Depuração tipo time-travel opcional**: reabrir um passo, editar estado/mensagem e criar fork (nova ramificação) em vez de sobrescrever; checkpoints por turno. Evidência: C30, C21.

## Antipadrões

- Esconder subagentes da lista de frota ou do painel de notificações (C6, C14).
- Grafo desenhado como única fonte de verdade, separado do arquivo/estado real (C32 mostra o contrário: grafo derivado do código).
- Swarm sem estrutura ou muitos papéis "para manter a máquina andando": custo e tokens altos com pouco ganho (C20, C28).
- Gerente que supõe estado compartilhado com os filhos e é prescritivo demais (C20).
- Propriedade de arquivos só "por conselho" no prompt, sem checagem (C4, C50).
- Sub-agente-como-ferramenta que só devolve string: perde ferramentas, trace e canal de mensagem (C37, C16).
- Aplicar multiagente a trabalho estritamente sequencial (C47) e ignorar falhas de papel/comunicação (C48).
- Depender de protocolo gráfico (Kitty/Sixel) sem fallback ou de Braille para texto (C40).
- Construir a visão em terminal só com strings ANSI concatenadas (C39).
- Adotar A2A/ACP/MCP Tasks como barramento interno por moda: A2A é inter-organização, ACP é UI↔agente, MCP Tasks é experimental (C44, C45, C46).
